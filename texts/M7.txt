M7. Базовая структура контента и управления, работающая на PHP.
2 ч по учебной программе

СОДЕРЖАНИЕ ПО ПРОГРАММЕ
Разделение данных, представления и управляющей логики. Назначение функций и компонентов серверного приложения. Принципы архитектуры MVC, маршрутизация запроса и организация файлов проекта.

МЕТОДИЧЕСКИЙ ТЕКСТ ПО ТЕМЕ

ТРИ ОТВЕТСТВЕННОСТИ
Модель работает с данными и правилами предметной области. Представление формирует интерфейс. Контроллер принимает запрос и координирует действия. Это архитектурная идея MVC, а не название отдельной CMS.

МАРШРУТ ЗАПРОСА
Точка входа выбирает сценарий по пути и методу, проверяет входные данные, вызывает нужную операцию и формирует ответ. Даже небольшой проект проще проверять, если HTML не смешан с SQL и обработкой всех действий в одном файле.

СТРУКТУРА ФАЙЛОВ
Публичный каталог содержит точку входа и статические ресурсы. Конфигурацию и серверные классы хранят за его пределами. Пример ниже не требует фреймворка и показывает разделение обязанностей; реальная модель может использовать PDO вместо фиксированного массива.

ПРИМЕР

// model.php
<?php
function getStudents(): array {
    return [["id" => 1, "name" => "Тимур"]];
}

// index.php — отдельный файл
<?php
require __DIR__ . "/model.php";
$students = getStudents();
require __DIR__ . "/view.php";

// view.php — отдельный файл
<ul>
<?php foreach ($students as $student): ?>
  <li><?= htmlspecialchars($student["name"], ENT_QUOTES | ENT_SUBSTITUTE, "UTF-8") ?></li>
<?php endforeach; ?>
</ul>

Результат: Раздели пример на три подписанных файла. index.php покажет список студентов.

Обратите внимание: CMS — готовая система управления содержимым; MVC — способ организации кода. Их нельзя считать синонимами.

ВОПРОСЫ ДЛЯ САМОПРОВЕРКИ
Где должен находиться SQL?
В слое доступа к данным, а не в шаблоне HTML.

Что делает контроллер?
Принимает запрос и связывает обработку данных с выбором ответа.
