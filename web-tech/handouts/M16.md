# M16. Обработка HTML-форм и проверка данных.

Учебный разбор, подготовленный по теме силабуса.

По силабусу: Передача данных методами GET и POST. Чтение значений на сервере, проверка типов и обязательных полей. Вывод сообщений об ошибках и корректное представление результатов.

## GET и POST

GET подходит для получения данных и поисковых параметров; POST — для отправки данных на обработку. В HTML-форме action задаёт адрес, method — метод, name — ключ поля. Наличие данных в теле POST не скрывает их от сервера, инструментов браузера и перехвата без HTTPS.

## Проверка на сервере

Проверь метод, наличие и тип каждого поля, затем допустимость значения и ограничения. Для ошибки подходит понятное сообщение возле поля; для программного API — статус и структурированный ответ. Клиентский required можно обойти, поэтому серверная проверка обязательна.

## Безопасный результат

Данные не нужно заранее преобразовывать в HTML-сущности перед хранением. Экранируй на границе вывода в конкретный контекст. Пример ниже не сохраняет данные и не выполняет изменение состояния; для операций изменения нужны проверка доступа и защита от CSRF.

## Пример

```php
<?php
$error = "";
$name = "";
if ($_SERVER["REQUEST_METHOD"] === "POST") {
    $raw = $_POST["name"] ?? "";
    $name = is_string($raw) ? trim($raw) : "";
    if ($name === "") {
        $error = "Укажите имя";
    }
}
function h(string $text): string {
    return htmlspecialchars($text, ENT_QUOTES | ENT_SUBSTITUTE, "UTF-8");
}
?>
<form method="post">
  <label for="name">Имя</label>
  <input id="name" name="name" value="<?= h($name) ?>" required>
  <button>Проверить</button>
</form>
<p><?= h($error !== "" ? $error : $name) ?></p>
```

Форма возвращает введённое имя безопасным текстом; пустое имя выдаёт сообщение «Укажите имя».

Обрати внимание: trim не является защитой от XSS или SQL-инъекции. Это только удаление краевых пробелов.
