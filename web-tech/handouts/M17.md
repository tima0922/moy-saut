# M17. Сессии и состояние веб-приложения.

Учебный разбор, подготовленный по теме силабуса.

По силабусу: Необходимость хранения состояния между запросами. Назначение сеансов и файлов cookie. Начало и завершение сеанса, обработка идентификатора и ограничения доступа к данным пользователя.

## Память между запросами

Сессия связывает запросы с серверным состоянием через идентификатор. Обычно браузер передаёт его в cookie. session_start запускает или восстанавливает сеанс и должен выполняться до вывода, если нужны HTTP-заголовки.

## Вход и проверка доступа

После успешной проверки учётных данных обновляют ID сессии. Пароль проверяют password_verify по хешу, созданному password_hash. Наличие session user_id само по себе не даёт право читать любую запись: авторизацию проверяют для конкретного действия и ресурса.

## Cookie и завершение

Для production-соединения HTTPS нужны подходящие параметры Secure, HttpOnly и SameSite. При выходе очищают данные и уничтожают сеанс; при полном удалении также удаляют cookie с теми же параметрами пути/домена. Ниже показан только счётчик посещений, без системы входа.

## Пример

```php
<?php
session_start();
$visits = (int) ($_SESSION["visits"] ?? 0) + 1;
$_SESSION["visits"] = $visits;
echo "Посещений в этом сеансе: " . $visits;

// После РЕАЛЬНОЙ успешной проверки пароля:
// session_regenerate_id(true);
// $_SESSION["user_id"] = (int) $user["id"];
```

Обновление страницы в той же сессии увеличивает счётчик. Это демонстрация состояния, а не авторизация.

Обрати внимание: Нельзя считать admin/12345 из архивной практики безопасной системой входа.
