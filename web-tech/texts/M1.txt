СОДЕРЖАНИЕ ПО ПРОГРАММЕ
Клиент-серверная архитектура и назначение веб-приложений. Понятия веб-страницы, сайта, домена и веб-сервера. Запрос и ответ HTTP. Роль клиентских и серверных языков в обработке пользовательского обращения.

МЕТОДИЧЕСКИЙ ТЕКСТ ПО ТЕМЕ

ОТ АДРЕСА ДО СТРАНИЦЫ
Веб-страница — документ, который браузер получает по адресу URL. Сайт объединяет связанные страницы и ресурсы. Домен помогает найти узел по имени; веб-сервер принимает HTTP-запросы. Браузер строит DOM из HTML, применяет CSS и исполняет клиентский JavaScript.

ЗАПРОС И ОТВЕТ
Запрос содержит метод, адрес ресурса и заголовки, иногда тело. Ответ содержит статус, заголовки и содержимое. 200 означает успешный ответ, 404 — ресурс не найден, 500 — ошибка на сервере. Запрос HTML часто вызывает дополнительные запросы CSS, скриптов и изображений.

ГРАНИЦА ОТВЕТСТВЕННОСТИ
PHP исполняется на сервере и может обращаться к БД. Браузер получает результат, а не PHP-код. HTTP не хранит состояние приложения сам по себе: для сеанса нужна дополнительная логика. HTTPS защищает данные при передаче; выбор POST вместо GET шифрования не добавляет.

ПРИМЕР

GET /index.html HTTP/1.1
Host: localhost:8000
Accept: text/html

HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8

<h1>Моя первая страница</h1>

Результат: Это схема двух сообщений HTTP/1.1: запроса и ответа. Проверить настоящий обмен можно во вкладке Network.

Обратите внимание: Не путай сайт, сервер и базу данных: браузер обычно обращается к приложению, а приложение — к БД.

ВОПРОСЫ ДЛЯ САМОПРОВЕРКИ
Что произойдёт при запросе PHP-страницы?
Сервер исполнит PHP и отправит получившийся ответ браузеру.

Почему у одной страницы несколько запросов?
HTML ссылается на отдельные CSS, JavaScript, изображения и другие ресурсы.
